# 决策记录

> 只写「代码里看不出来、且全仓库为真」的判断。能写成脚本或检查的都进了 `hooks/`，
> 判据来自课程 p013 [00:58]：「这一行留着的条件是：Agent 自己看不出来，且在整个仓库处处为真」。

## D1. 状态徽章用 `<= 0` 判售罄，不用 `< 0`

课程 p044 埋的 bug 就是这条：`< 0` 让「刚好 0 张」显示成 few left，客户要到下单页才发现。
**所以任何「余量」判断，先想清楚 0 属于哪一侧。**

## D2. MCP server 不引第三方 SDK

课程要求「一个文件、stdio、无登录」。MCP 就是 JSON-RPC 2.0 over stdio，手写约 120 行，
换来的是能在沙箱里零依赖启动——盒子里 npm 装包失败时，server 仍然能跑。

## D3. 危险动作只返回确认链接，不真执行

来自课程 P39 的最佳实践：`cancel_event` 只返回「影响 + 确认链接」，人点确认后才真的取消。
Agent 可以建议，不可以代替人按下不可逆的按钮。

## D4. 阻断型 hook 必须给出替代路径

课程 p017 [01:21]：「block 时一定要告诉 Agent 改做什么」。
只拦不指路，模型会在同一个地方反复撞墙，烧掉的是上下文预算。

## D5. 凭据按内容判定，不按文件名

`.env` 要拦，`credentials.json` / `auth.json` / `settings.json` / `id_rsa` / `.npmrc` 同样要拦。
判定标准是「这个文件里可能有凭据」，不是「文件名长得像 .env」。
