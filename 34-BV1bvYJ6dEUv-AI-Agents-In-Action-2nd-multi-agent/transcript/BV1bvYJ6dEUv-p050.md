The termination gate is the decision point at the end of each iteration that determines whether the loop continues or exits. As we established earlier, termination conditions should always be layered. Here is an example of some priorities you may want to consider. Hard limit.
[06:26] Maximum iteration count. This is your safety net and should always be present. Setting this limit depends on how long you want the agent to run to produce good output. Budget limit. Maximum token or cost spend. Critical for production systems with cost constraints. To better control costs, reduce the number of tokens an agent consumes per iteration. Goal satisfaction. The agent declares that its goal has been met. This is the ideal exit path.
[06:55] but it is also an internal self-assessment that could be biased. To address this bias, you could introduce another goal agent to make this decision. Quality Threshold An external evaluator or the agent's own self-evaluation exceeds the minimum confidence bar. Since this is a self-assessment, you may want to use a quality agent or a combined goal quality agent to control it. Stagnation Detection
[07:21] The agent's output has not meaningfully changed for N iterations. This prevents loops that produce diminishing returns. The two context function can help normalize outputs and track major changes. Hard limits and budget limits are defensive and non-negotiable. Goal satisfaction and quality thresholds indicate that the agent is doing its job well. Stagnation detection is the safety valve for cases where the agent isn't failing, but also isn't making progress.
[07:49] endlessly rephrasing the same findings or running similar searches. Stagnation is harder to detect than failure. A failing agent throws errors or returns empty results, both of which are easy to catch. A stagnating agent returns plausible looking output that is not meaningfully different from what it produced two iterations ago. To detect this, compare the semantic overlap between consecutive iteration summaries.
[08:15] You can check semantic overlap by converting both sets of text to vector embeddings and then measuring cosine similarity. If the overlap exceeds a threshold, say 85%, for two consecutive iterations, terminate the loop and return what you have. The extra iterations are not adding value. The cost of unconstrained loops. An agentic loop without a hard termination condition is a production incident waiting to happen. Every iteration consumes tokens,
[08:45] incurs API costs, and adds latency. During development, it is tempting to let the agent loop until it is satisfied, but in production, you must always set a maximum iteration count and cost ceiling. Even if you trust the agent's judgment on convergence, a defensive maximum protects you from edge cases where the model gets stuck in a reasoning loop or keeps searching for information that does not exist. [13:27] when to use an agentic loop. Not every agent needs a loop. Use the agentic loop when the task has one or more of the following characteristics. Iterative discovery. The agent cannot get all the information it needs in a single step. Research, analysis and exploration tasks almost always fall into this category. Progressive refinement. The output improves with each iteration.
[13:53] Writing, summarization, and content generation can benefit from iterative drafts. Batch processing. There is a queue of items to process, and the agent works through them one at a time or in small batches. Conditional branching. The agent's next action depends on the result of the previous action. Diagnostic agents, troubleshooting flows, and decision trees use this pattern. Multisource aggregation.
[14:21] The agent needs to combine information from multiple sources, and the relevant sources are discovered during execution rather than known in advance. Conversely, avoid the agentic loop for tasks that require a single pass. Classification, simple question answering, and format conversion rarely benefit from iteration. Adding a loop to these tasks only adds latency and cost without improving quality. Section 9.2.8
