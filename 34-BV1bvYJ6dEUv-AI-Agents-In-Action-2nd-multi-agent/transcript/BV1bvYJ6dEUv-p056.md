[04:37] Section 10.2.3 – The Perception Module The perception module is the agent's first contact with reality. It takes the raw user query and transforms it into a structured task representation in the workspace. This is not just parsing. It involves understanding and classifying the problem, extracting key entities, identifying ambiguities, and estimating the task's complexity. The complexity estimate is particularly important
[05:04] because it determines how deeply the rest of the architecture engages. A complexity estimate below 0.3 might trigger the system one fast path, skip planning and evaluation, and go straight to execution. A complexity estimate above 0.7 triggers the full cognitive cycle. This is Kahneman's dual process theory implemented as a routing decision.
[05:31] You can think of the Perception Module's role as a form of triage applied to the initial user query, producing a task representation that classifies how the query will be processed. Section 10.2.8 The Memory Module and the MCP Memory Server The memory module provides the cognitive agent with persistent long-term memory using at model context protocol slash server memory, the official reference memory server from the MCP project. This server implements a local knowledge graph with three primitives, entities, the primary nodes, relations,
[12:59] directed connections between entities stored in active voice, and observations, discrete pieces of information attached to entities. No external database or embedding service is required. The server runs locally and persists in a JSON file. We previously explored the server in Chapter 5 on memory and knowledge. This knowledge graph structure maps naturally to how the cognitive agent thinks about its own experience. Problem types become entities.
[13:27] Strategies that worked become observations attached to those entities. Relations connect related problem types, successful tool combinations, and known failure modes. Over time, the knowledge graph becomes the agent's institutional memory, not a flat log of past interactions, but a structured model of what it has learned. [15:19] The reference MCP memory server uses a knowledge graph rather than vector embeddings. This is a deliberate trade-off. Vector stores find things that look similar. Knowledge graphs find things that are structurally related. For the cognitive agent, structural relationships matter more than surface similarity. Knowing that timeout errors under load and connection pool exhaustion are related problem types via a shared relation is more useful than knowing they have similar embedding vectors.
