[00:00] Section 1.3 Overview of Orchestration In distributed applications, orchestration refers to the management and coordination of individual services or components within a larger system. When you build a distributed system composed of multiple services, containers or other components, orchestration is crucial for ensuring that these elements work together seamlessly to achieve the desired outcome. Orchestration involves tasks such as deployment, scaling,
[00:29] health monitoring, and resource allocation across the distributed environment. Figure 1.4 shows how the process of orchestration works. Figure 1.4. An orchestrator coordinates separate services over the network in a distributed application and ensures that they act as one functioning system. To understand orchestration, consider what must happen before a shopper can browse the product catalog.
[00:58] The storefront can't retrieve product data unless the catalog API is running. The catalog API may itself depend on a database or cache. Later, order processing will require a message broker and a background service. Each resource must be started with the correct configuration, and dependent services shouldn't begin work until the resources they need are ready. An orchestrator coordinates this process. First, it starts the resources that form the application.
[01:25] For the online shop, this may include the storefront, catalog API, database, cache, message broker, and background service. Instead of requiring a developer to launch each component manually, the orchestrator provides a single way to start and manage the complete system. As the resources start, the orchestrator supplies the configuration they need. The storefront must know how to reach the catalog API, and the API may need connection information for its database and cache.
[01:55] These addresses and connection details can vary among development, testing and production environments, so they shouldn't be hard-coded into the application. The orchestrator also tracks dependencies and readiness. A process may be running without being ready to accept requests. A database container, for example, may need time to initialize after it starts. The orchestrator can use health information to determine when a resource is ready and delay dependent services until the resources they require are available.
[02:24] When the application is running, orchestration provides a view of the system as a whole. If the catalog API becomes unhealthy, developers must see that its failure affects the storefront. In production environments, an orchestration platform may also restart failed instances, route traffic to healthy replicas, or increase the number of running instances when demand grows. The exact responsibilities depend on the environment. Production orchestration platforms commonly manage deployment, scaling,
[02:54] load balancing, resource allocation, and recovery across servers or clusters. ASPIRE's immediate role is development time orchestration. It helps you describe the application's resources and relationships, start them together, supply configuration, assess their health, and inspect them through a shared dashboard. The services remain independently running components. Orchestration doesn't remove the boundaries between them. It makes those boundaries easier to manage.
