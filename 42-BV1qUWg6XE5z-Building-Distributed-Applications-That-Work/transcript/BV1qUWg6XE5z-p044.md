Integration tests are a special category of automated tests that allow us to verify that an application or one of its modules works as intended with other components. These tests may use real networks, real HTTP requests, real database connections and so on. Traditionally, integration tests were fairly hard to apply to orchestrated distributed applications
[01:25] because such applications have many moving components that must be coordinated. Typically, running all these components is computationally expensive. Therefore, the scope of integration testing in distributed applications is usually limited to interactions among a small number of components. But Aspire solved this problem quite neatly. Its developers at Microsoft thought ahead to integration tests, so running integration tests against it is almost as easy as running low-level component unit tests.
