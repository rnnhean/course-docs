[00:57] These parts work together as one system. A system structured this way is known as a distributed application. On a development machine though, separate components often have to be started individually. Each resource needs the correct configuration. Services need to know where their dependencies are running. Containers need ports and volumes. One service may start before another is ready. When something fails, its logs may be hidden in one of several terminal windows. If you're a .NET developer,
[01:26] you can use a tool that solves this major pain point of cloud application development. This tool is Aspire, formerly known as .NET Aspire. Aspire is designed to make this development experience more manageable. It provides a code-first application model for describing the services and infrastructure resources that form a distributed application. The central project in this model is the App Host. In App Host code,
[01:52] You declare the resources in the system and describe the relationships between them. Then Aspire can use that model to do the following. Start the application's resources together. Supply configuration and connection information. Coordinate dependencies among resources. Enable services to locate one another through service discovery. Display resource state and telemetry in a shared dashboard.
[02:19] The individual services remain independent applications. Aspire doesn't merge them into one executable and it doesn't replace the production platform on which they'll eventually run. Instead, it gives developers one place to model, run, debug, and observe the complete system.
