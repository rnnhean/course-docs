The integrations are based mostly on Docker containers, but the libraries that enable them have a range of extension methods that make it much easier to host these components in Aspire than work with Docker containers directly. Not all Aspire integrations are based on Docker containers, however. An Aspire integration for a database provider, such as SQL Server,
[00:57] might be configured to connect to a managed SQL Server instance that isn't hosted inside a container. Hosting the SQL Server instance in a container would be a terrible idea unless it's done purely for development or demonstration purposes. Containers are meant to be stateless, which makes them highly unsuitable for storing data. If anything happens to the server that hosts the container, the container will recover, but it will be reset to its original state, so you'll lose all your data.
